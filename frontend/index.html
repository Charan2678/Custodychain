How CustodyChain Verifies Integrity

3 independent cryptographic checks executed at every handler
1

Independent Mathematical Recomputation

CustodyChain does not rely on self-declared logs. It pulls the raw stored artifact byte-stream from disk and recomputes the SHA-256 hash independently. If a single bit or CRLF newline was altered, the hash will not match.

2

Ed25519 Cryptographic Signatures

Every handler transition is signed with an asymmetric Ed25519 private key belonging to the designated custodian or automated tool. The public key verifies identity, ensuring non-repudiation and detecting forged records.

3

Previous-Event Hash Continuity (Ledger Link)

Each event payload references the cryptographic hash of the preceding event, creating an unbroken chain of custody. If any prior record is retroactively deleted or altered, the entire subsequent chain fails.
